7. Failover and resilience

Multi-AZ by default

  • Lambda, API Gateway, DynamoDB, SQS, SNS, Step Functions and EventBridge are regional and span AZs (Azure: zone-redundant Functions Premium, Cosmos DB, Service Bus Premium).
  • ElastiCache with Multi-AZ replica and automatic failover (Azure Cache for Redis zone redundancy).
  • OpenSearch with 3 AZs and dedicated masters (Azure AI Search with replicas).
  • Optional second region: DynamoDB global tables (Cosmos DB multi-region writes) and Route 53 / Front Door health-based routing.

Retries and dead-letter queues

  • Step Functions Retry with exponential backoff and jitter, then Catch into the compensation path.
  • Every SQS / Service Bus consumer has a DLQ after 5 receives; alarm on DLQ depth above 0.
  • EventBridge rules have their own DLQ and retry policy.
  • Payment and recommendation calls have tight timeouts and circuit breakers.

Idempotency

  • Checkout requires an Idempotency-Key; a retry returns the stored response, not a new order.
  • Payment provider calls reuse the order ID as their key, so a retried charge never double-charges.
  • Event consumers dedupe on event ID, so at-least-once delivery is safe.

Graceful degradation

  • Recommendations or concierge down: show best sellers; checkout is unaffected.
  • Search down: fall back to category browse from the catalog table.
  • Redis down: read straight from DynamoDB / Cosmos DB at higher latency.
  • Fail closed on money and stock: never confirm an order without a captured payment and a reservation.

9. Testing

1. Load testing

  • Tooling: k6 or Locust, run at scale with Distributed Load Testing on AWS (Azure Load Testing on Azure).
  • Mix: 70% browse, 20% search, 8% cart, 2% checkout (example), with a payment provider sandbox or stub.
  • Patterns: steady, spike (10x in 60 s, like a flash sale) and 8-hour soak.
  • Watch DynamoDB throttles, Lambda concurrency, Redis CPU and queue depth.

2. Latency validation

  • P50, P90 and P99 per path from k6 results plus CloudWatch metrics and AWS X-Ray traces (Application Insights on Azure).
  • Pass only if every path meets the targets above at peak load, including the spike.
  • Break checkout down by saga step to find the slow span.

3. Checkout saga and compensation

  • Happy path: reserve, charge, confirm, OrderPlaced published exactly once.
  • Inject failures at each step: out of stock, payment declined, payment timeout, confirm failure.
  • Assert the right compensation ran: stock released, refund issued, order in the correct final state.
  • Kill a Lambda mid-step with AWS Fault Injection Service and check the saga resumes or compensates.

4. Payment idempotency

  • Send the same checkout with the same Idempotency-Key 10 times in parallel: one order, one charge.
  • Replay provider webhooks and out-of-order webhooks: payment status stays correct.
  • Timeout then retry: the provider is queried by key, never charged twice.

5. Inventory oversell

  • Stock of 5 units, 100 concurrent checkouts: exactly 5 succeed, 95 get OUT_OF_STOCK.
  • Multi-line orders reserve all lines or none.
  • Expired reservations return stock; available never goes below zero.

6. Concierge guardrail (optional)

  • Golden set of bundle requests: every presented bundle passes price, stock, compatibility and budget checks.
  • Feed the guardrail incompatible accessories, stale prices and expired offers: each must be rejected.

7. Regression testing and CI

  • pytest: regression tests for cart pricing, inventory reservation, saga state transitions, idempotency handling and the concierge validation rules, with pytest.mark.parametrize for boundary cases and shared conftest fixtures (sample catalog, carts, stock levels).
  • Playwright: UI checkout tests end to end: search, add to cart, sign in or guest, pay with a sandbox card, see the confirmation; plus a declined-card path.
  • CI: the suite runs on every change (AWS CodePipeline with CodeBuild, Azure DevOps Pipelines or GitHub Actions); a failing saga, idempotency or oversell test blocks the merge and the deploy.
  • Reporting: results pushed as CloudWatch / Azure Monitor metrics with an alarm on any failure.
